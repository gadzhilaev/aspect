# Сайт → backend мобильного разработчика

Дата: 2026-10-26.

Цель API: `aspect-backend-20261025/backend`. Изменения только в `frontend/`.
Старый и мобильный backend, миграции, БД, стенды и процессы не изменялись.

## Что адаптировано

- «Компания → Продукция»: GET/PATCH `/api/v1/companies/{company_id}/industry-profile`.
  Деятельность, категории, бренды, линейки, рынки и страны закупок.
  PATCH содержит только изменённые поля. Пустое значение отправляется как `[]`.
  Валюты и остальные настройки не перезаписываются. При смене компании форма перемонтируется.
  Ошибка GET не маскируется под пустой профиль.
- Лента: `industry_profile_match` и `case_profile_match` не отображают индекс,
  confidence или экспозицию; CTA ведёт в обсуждение, не на отсутствующий Impact.
  Известный нулевой calculated Impact остаётся нулём.
- `/settings`: тема аккаунта, смена пароля и удаление с вводом пароля и подтверждением.
  Используются существующие preferences/change-password/DELETE endpoints.
  При ошибках (включая SOLE_OWNER / HAS_AUDIT_RECORDS) сессия не объявляется удалённой.
  Password-401 не вызывает автоматический refresh/retry. После успеха смены/удаления локальная сессия очищается.
  Язык не переключается: веб-переводов нет, чужая настройка `language` сохраняется.
- Сохранённая тема применяется при загрузке аккаунта. Переключатель в header остаётся локальным;
  запись общей с мобильным приложением темы выполняется кнопкой в настройках.
- Завершение мастера отмечает `registration_complete=true`; вход с готовой компанией также
  отмечает завершение, если флаг отсутствует. Ошибка этого запроса не выдаётся за успешный вход.
- Убраны предзаполненные старые demo-пароли.
- В хаб компании возвращён существующий блок `CaseContextSection` с полным контекстом API;
  сбой загрузки источника отображается отдельно от ручного профиля.
- `/notifications`, банк, PDF с Bearer, assistant и финансовый мастер используют существующие API.

## Запуск только фронтенда

Backend запускает его владелец. В PowerShell из frontend:

```powershell
.\run_mobile_web.ps1 -ApiUrl http://127.0.0.1:8020
```

8020 — пример, а не подтверждение запущенного процесса. Укажите фактический origin
API именно мобильного backend. Скрипт проверяет `/health`, запускает только Vite на 5181
и не занимает другой порт автоматически. `/health` сам по себе не доказывает версию backend.

Для ручного запуска: `npm run dev:mobile`. `.env.mobile` задаёт публичный dev proxy
на 8020 и отдельное пространство токенов `aspekt.mobile-backend`. При смене сервера выйдите
из аккаунта перед повторным входом. Переопределение адреса: `.env.mobile.local` → `VITE_PROXY_TARGET`.
Старый `.env` не редактировался.

Production: `npm run build:mobile`. Сборка обращается к `/api` на том же origin —
хост сайта должен проксировать `/api` в новый backend. Vite proxy работает только при разработке.
Либо задайте публичный `VITE_API_BASE_URL` при сборке; тогда CORS на сервере настраивает владелец backend.
Никаких LLM/DaData/Telegram ключей в VITE-переменных.

## Наблюдения о неизменяемом backend

1. Сохранённый `contracts/openapi.json` отстаёт от Python: в файле нет industry-profile
   и registration_complete. Адаптация выполнена по существующим роутам и схемам Python,
   файл OpenAPI backend не менялся.
2. Поисковые интересы пока не подключены к ingestion/scheduler. Форма обещает подбор
   опубликованных новостей, не полноценный внешний поиск по бренду.
3. Регистрация может перезаписать пользователя без registration_complete. Клиент отправляет
   этот флаг на завершении, но не может устранить серверный риск для незавершённых аккаунтов.
   Перед публичным размещением это должен оценить владелец backend.
4. В этом Python-коде нет PATCH `/users/me` для имени. Редактор имени не добавлялся.

## Ручная приёмка на нужном API

1. Войти реальными учётными данными этого сервера; проверить выбранную компанию.
2. Компания → Продукция: загрузить, изменить бренд, сохранить, перезагрузить страницу.
3. Переключить компанию: предыдущие интересы не должны остаться в форме.
4. «Для вас»: тематическое совпадение → обсуждение без числового индекса;
   отсутствие совпадений допускается, данные не подставляются.
5. Настройки: сохранить тему; проверить ошибочный текущий пароль и серверный отказ удаления.
   Успешное удаление проверять только на специально созданном тестовом аккаунте.
6. Новость → обсуждение → источник банка → PDF; финансы → расчёт → решение.
7. Проверить мобильную ширину и светлую/тёмную темы.
