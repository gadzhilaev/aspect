## 3. Файлы по отдельности

### 3.1. `df_Uid_data_hack.csv` — компании

**Строки данных:** 85 525 (+ заголовок).  
**Уникальных `SYNTHETIC_U`:** 85 514.  
**Дубликаты ключа:** 1 UID (`U_428697`) встречается **12** раз (11 лишних строк в хвосте файла); строки **не идентичны** — расходятся ОКVED, выручка, город/регион, `GROUP_ID` и др. При импорте нужна явная политика дедупликации.

**Колонки (24):**

| Колонка | Содержание (агрегат) |
|---------|----------------------|
| `SYNTHETIC_U` | ID организации (`U_*`), почти уникален |
| `ORG_TYPE` | всегда `КОММ_ОРГ` (1 значение) |
| `OKFS_NAME` | форма собственности (12 значений; ~96% «ЧАСТНАЯ СОБСТВЕННОСТЬ») |
| `COMPANY_AGE_YEARS_GRADATION` | возраст: `0-3`, `4-7`, `8-15`, `16-25` |
| `ECO_MARK_LABEL` | жизненный цикл/сегмент; **4 151** пустых |
| `MAINOKVED_CODE` / `MAINOKVED_NAME` | основной ОКВЭД; **546** уникальных кодов |
| `NEGATIVEMARK` | `0.0` / `1.0` (~13% с меткой 1) |
| `AMOUNT_WORKERS_FNS_GRADATION` | численность ФНС: 4 градации |
| `AMOUNT_WORKERS_SPARK_GRADATION` | почти пусто (**~85 357** пустых) |
| `CL_TYPE` | `CLIENT` / `PROSPECT` / `CLOSE_CLIENT` |
| `CL_PRODUCT_*_MARK` | флаги продуктов банка (РКО, гарантии, кредиты, лизинг, депозиты, ЗП) — `0.0`/`1.0` |
| `FTS_FLAG` / `FTS_COUNTRY_NAME` | ВЭД-признак; страна заполнена не всегда (при `FTS_FLAG=1` есть пустые; часто списки стран через запятую) |
| `FACTORING_MARK` | почти всегда 0 |
| `REVENUE_COMPANY` | числовая выручка; min≈1 000, p50≈33.6 млн, max≈105.6 млрд; нулей/отрицательных нет |
| `GROUP_ID` | группа компаний; **18 092** групп; много синглтонов; max размер группы 624 |
| `CITY` / `REGION` | география; пустых нет; 82 региона |

**Пропуски (пустое поле):** `AMOUNT_WORKERS_SPARK_GRADATION`, `ECO_MARK_LABEL`, частично `FTS_COUNTRY_NAME`. Явных `NULL`-токенов нет.

**Единицы `REVENUE_COMPANY`:** **неизвестно** (в данных и репозитории не указаны).

## 4. Связность между файлами

```
df_Fid_Uid_link_hack.SYNTHETIC_U ──► df_Uid_data_hack.SYNTHETIC_U
df_Uid_payment_hack.BENEFICIARY  ──► df_Uid_data_hack.SYNTHETIC_U  (частично)
df_Uid_payment_hack.PAYER        ──► df_Uid_data_hack.SYNTHETIC_U  (частично)
```

### 4.1. Платежи ↔ компании

| Метрика | Значение |
|---------|----------|
| Обе стороны есть в справочнике компаний | **389 396** рёбер (**28.2%**) |
| Нет бенефициара, плательщик есть | 409 024 |
| Нет плательщика, бенефициар есть | 582 165 |
| Обе стороны отсутствуют | **0** |
| Уникальных `U_*` только в платежах (нет в справочнике) | **114 552** |
| Компании справочника без участия в платежах | **21 907** |

**Вывод:** граф платежей шире справочника компаний. «Сиротские» стороны платежей — это не битые строки целиком: у каждого ребра есть хотя бы один известный endpoint, но контрагент часто отсутствует в `df_Uid_data_hack`.

### 4.2. Связи физлиц ↔ компании

| Метрика | Значение |
|---------|----------|
| Строк связи с `SYNTHETIC_U` **вне** справочника | **7 885** из 12 514 (~63%) |
| Компаний справочника, покрытых хотя бы одной связью F | **4 519** из 85 514 (~5.3%) |

**Вывод:** файл связей покрывает малую долю компаний; большая часть ссылок указывает на `U_*`, которых нет в `df_Uid_data_hack`.

### 4.3. Подтверждённые связи

1. Общий идентификатор организаций: `SYNTHETIC_U` ↔ `BENEFICIARY` / `PAYER` (префикс `U_`).
2. Связь физлицо→организация: `SYNTHETIC_F` → `SYNTHETIC_U`.
3. Группировка компаний: `GROUP_ID` внутри справочника.
4. Платёжное ребро: направленная пара `(PAYER → BENEFICIARY)` с суммой и счётчиком.

## 7. Рекомендации к проектированию импорта (без реализации)

На этапе проектирования импорта потребуется явно зафиксировать:

1. Политику дедупликации `SYNTHETIC_U` (особенно конфликтный UID).
2. Стратегию сирот платежей и связей F–U (stub / drop / отдельная таблица «unknown party»).
3. Нормализацию `FTS_COUNTRY_NAME` (мульти-страны в одной строке).
4. Запрос к организаторам кейса: единицы денег, период `PAY_*`, семантика связи F–U и `ECO_MARK_LABEL` / `RC_NAME`.

**Импортёр, миграции, БД, API и UI на этом этапе не менялись.**
