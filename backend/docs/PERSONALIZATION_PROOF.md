# Personalization proof — доказуемая персонализация

Дата: 2026-10-19  
База: `docs/ASSESSMENT_TRUST_AUDIT.md` (impact-v1.1, `score_kind`, exposure null≠0).

## 1. Профили A и B

| | Компания A — СеверПром | Компания B — ВолгПром |
|---|---|---|
| ID | `cmp_severprom` | `cmp_volgaprom` |
| Demo user | `demo@kontur.app` | `demo_volga@kontur.app` |
| Поставщик | Shenzhen X (**Китай**) | ООО КомплектПром (**Россия**) |
| Компонент | Электронный модуль B (`electronics`) | тот же тип компонента |
| Линия | Линия №2, доля **24%** | Линия №1, доля **30%** |
| Валюты закупок | RUB, CNY, USD | RUB |
| Китай в twin | да (supplier) | нет |

Событие: `evt_china_export_001` — демо-ограничение экспорта электроники из Китая.

## 2. Результаты одной новости

| Компания | Найденная связь | Тип оценки (`score_kind`) | Объяснение | Доступное действие |
|---|---|---|---|---|
| A СеверПром | Поставщик Китай → модуль B → Линия №2 | `company_calculated` | Страна поставок + цепочка + доля выпуска | Impact, сценарии, ассистент |
| B ВолгПром | Прямая связь **не** установлена | — (нет активного impact) | Российский поставщик; происхождение его закупок в профиле не задано; материалы/валюта сами по себе не открывают карточку | Публичная новость + блок релевантности; уточнить профиль |

Различия следуют из **роли страны** (supplier vs market) и наличия поставщика в стране события — не из имени компании и не из hardcode event×company.

## 3. Основания различий (логика)

1. **Совпадение признака** ≠ **зависимость**. Материалы `electronics` у B есть, но для export/geopolitics gate требует **supplier country**.
2. **Рынок продаж** в Китае не считается основанием для export-control (отдельно от страны поставок).
3. **Достаточность данных**: у A есть path + known exposure → `supply_chain_ready` / `company_calculated`. У B нет релевантности → impact не создаётся (или помечается `not_relevant` после снятия связи).
4. Provenance: `GET /events/{id}/relevance?company_id=` и `score_breakdown.relevance` / `assessment_basis.relevance`.

## 4. Изменение профиля B

Штатный цикл: правка узлов → `POST .../digital-twin/build` → `recompute_events_for_company`.

| Шаг | Ожидание |
|---|---|
| Добавить поставщика из Китая + edge к компоненту | Активный impact, `company_calculated`, без дубля строки |
| Убрать связь | `status=not_relevant`; число прошлого расчёта **не** переписывается; paths сняты с активной карточки; чаты/решения не удаляются |
| GET relevance / public news | Без создания impact |

## 5. Сортировка персональной ленты

Группы (не смешивать смысл чисел):

1. `company_calculated`
2. `event_severity_signal`

Внутри группы: `impact_score DESC`.  
Cursor: `{group}:{score}` (legacy bare score = group 0).  
`not_relevant` не попадает в ленту по умолчанию.  
Поле `feed_sort_rule` в dashboard / events list.

## 6. Команда демо-профилей и показ

```text
# 1) Основной демо (A) — уже в seed_demo
python -m scripts.seed_demo

# 2) Контраст (B) — идемпотентно; НЕ запускать агентом на рабочей БД пользователя
python -m scripts.seed_demo_contrast
```

Последовательность ручного показа:

1. Войти как `demo@kontur.app` → «Для вас» / impact China → цепочка и индекс.
2. Выйти, войти как `demo_volga@kontur.app` → публичная новость China открывается; персональный блок объясняет отсутствие прямой связи; в «Для вас» нет подтверждённого China impact.
3. (Опционально) Через setup/API добавить китайского поставщика B → `digital-twin/build` → появляется персональная оценка.
4. Убрать связь → снова `build` → карточка не актуальна (`not_relevant`).

**ACL:** нет публичного сравнения компаний; нет переключения `company_id` без membership.

## 7. Проверки

Автотесты (`tests/test_personalization_proof.py` + регрессии):

- разные результаты A/B на одной новости;
- одинаковая логика при смене названия компании;
- рынок ≠ поставщик; чужая страна не даёт цепочку;
- materials alone не открывают China export для B;
- add/remove China link + нет дублей;
- feed groups;
- public news без personal impact;
- ACL B ↛ A;
- GET relevance без side-effect.

Полный `pytest` и `npm run build` — после завершения этапа.

## 8. Ограничения

- Ассистент по-прежнему требует **активный** EventImpact (для B без связи — через UI релевантности, не через чат).
- Косвенная зависимость российского поставщика от Китая **не моделируется** без данных в twin.
- Маркетинговые «87» на about/home не являются live-оценкой.
- `seed_demo_contrast` готовит данные для демо; агент не применяет его к рабочей БД пользователя.
